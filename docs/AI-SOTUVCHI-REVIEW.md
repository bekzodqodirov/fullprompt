# AI sotuvchi — review of phase 1 before code (2026-10-24)

The design in `docs/AI-SOTUVCHI.md` §16 was judged by six lenses before a line of it was written — the spec's
five (leak, regression, product fit, ban risk, money) plus a sixth for the house's own fences — each a finder who
traced every objection to the code and a skeptic who tried to refute each one against the code. **78 objections:
48 confirmed, 30 partial, 0 refuted.** Every one is answered below by a BINDING fix: where a fix and the
spec's text disagree, the fix wins, and §17 of the spec restates the design as it will be built. A fix marked
DEVIATION departs from what the finder or skeptic proposed, with the reason on the line. The owner's decisions in
§15 are not reopened; what the lenses wanted to ask him went to him as questions on 2026-10-24 (§17.0) and is
built with the recommended ⭐ until he answers.

The two decisions that change the most:

- **Agent replies never enter `tg_outbox`.** Nine regression and build objections were the shape «an agent row
  inside the human queue» — status hand-backs, a nullable client in four readers that cannot see it, the old pump
  claiming a new row. A separate `agent_outbox`, drained by the same listener after the human rows, leaves every
  existing writer, reader and CHECK of `tg_outbox` byte-identical.
- **No new column on any existing table.** Every new fact (pause, flood, deleted, auto-sent, readiness) lives in a
  new table, so a database one migration behind answers every existing whole-row read exactly as today (build-10).
